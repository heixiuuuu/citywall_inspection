# 系统架构

四端使用 HTTP API 交互，管理端与巡检端仅访问业务后端。识别服务位于内部网络，不持有业务用户令牌或数据库权限。

| 端 | 技术 | 输入与输出 |
| --- | --- | --- |
| 巡检端 | uni-app / Vue 3，Android WebView | 任务、照片、WGS84 位置、候选判定及人工结论 |
| 管理端 | Vue 3 / TypeScript | 城墙区段与点位档案、任务派发、证据复核、问题处置及报告 |
| 业务后端 | Go / Gin / GORM / MySQL | 身份权限、任务与记录状态、文件鉴权、识别编排及报告快照 |
| 识别端 | FastAPI / YOLO / 视觉模型适配 | 图片校验、候选类别与坐标、现象描述、可能成因及复查建议 |

## 数据流

任务草稿选择点位和巡检员，派发时保存点位快照。巡检员创建现场记录并上传概览及细节图片，后端保存受控文件后调用识别端。每次识别使用独立 attempt，成功、失败及视觉模型分析分别保留。

巡检员确认、修改或拒绝候选，也可补录漏检。人工结论按版本保存，提交时冻结位置、图片和结论引用。审核员可通过或退回；主动上报可驳回。审核通过后新建问题、关联已有问题或记录不立项原因。

问题独立于任务流转，支持指派、处理、观察、核验和关闭。报告保存生成时的数据快照，包含照片、人工结论、复核及处置状态；既有报告不跟随后续记录变化。

## 部署

Docker Compose 运行 MySQL、Go、Python 和 nginx。容器间通过服务名连接。MySQL 数据与业务文件采用独立命名卷，配置只读挂载；YOLO 权重从 data/yolo 挂载。识别服务仅在内部网络开放。

开发者通过主机执行单元测试和前端构建。隔离业务测试采用独立 Compose 项目和端口，结束后删除该项目的容器与卷。

## 人工判断边界

检测置信度不表示病害严重度，零检测不等于正常。视觉模型的可能成因和建议为辅助文本，不能成为结构安全鉴定。模型与分析服务不可用时可人工填写现场记录，不能伪造模型输出。
