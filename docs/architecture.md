# 系统架构

四端使用 HTTP API 交互，管理端与巡检端仅访问业务后端。识别服务位于内部网络，不持有业务用户令牌或数据库权限。

| 端 | 技术 | 输入与输出 |
| --- | --- | --- |
| 巡检端 | uni-app / Vue 3，Android WebView | 任务、照片、WGS84 位置、候选判定及人工结论 |
| 管理端 | Vue 3 / TypeScript | 城墙区段与点位档案、任务派发、证据复核、问题处置及报告 |
| 业务后端 | Go / Gin / GORM / MySQL | 身份权限、任务与记录状态、文件鉴权、识别编排及报告快照 |
| 识别端 | FastAPI / YOLO / 视觉模型适配 | 图片校验、候选类别与坐标、现象描述、可能成因及复查建议 |

## 数据流

管理端工作台供管理员和审核员查看全库任务、记录与问题概况，聚合在只读可重复读事务内读取。病害分布只计审核通过记录最后一次提交冻结的人工结论项，排除误检和历史版本；该数量不代表去重后的现场病害数量。待受理入口按已通过且受理时间为空筛选，直接进入对应记录列表。

任务草稿选择点位和巡检员，点位及其所属区段均须启用，派发时保存点位快照；档案停用不改变既有快照。巡检员创建现场记录并上传概览及细节图片，后端保存受控文件后调用识别端。每次识别使用独立 attempt，成功、失败及视觉模型分析分别保留。

任务创建在同一事务内写入任务和任务点。派发锁定任务后校验状态及版本，将全部点位快照与派发状态共同提交；任一写入失败完整回滚，相同版本的并发派发不能改写成功请求的快照。

任务取消或完成后停止新建和修改采集记录、照片关联、新识别及提交，已有证据仍可读取，已提交记录保留审核权限。采集写入与任务取消使用相同任务行锁；现场记录提交与任务进入进行中状态共享事务，任一状态保存失败均回滚提交快照。巡检端将已结束任务的草稿转入只读详情，已受理问题继续独立处置。

巡检员确认、修改或拒绝候选，也可补录漏检。人工结论按版本保存，提交时冻结位置、图片和结论引用。审核员可通过或退回；主动上报可驳回。审核通过后新建问题、关联已有问题或记录不立项原因。

记录修改、人工结论、提交与审核均锁定现场记录，并在同一数据库事务内校验状态与 revision、保存关联数据及更新状态。任一写入失败会回滚该次业务修改；同一 revision 的并发请求只能有一个成功。图片关联和移除受相同记录锁约束，待审核、已通过和已驳回状态禁止修改当前照片关联。

现场照片上传在记录锁内完成权限及状态校验、图片登记和关联，登记或关联失败时回滚元数据并清理未提交文件，失败请求可重试。问题处置照片复用同一受控文件清理能力。

退回补正可以更换当前照片关联，原提交中的位置、照片和人工结论引用仍保留。记录详情按提交版本提供只读快照，识别尝试按完成时间筛选；历史照片按原记录权限鉴权，未提交过的已移除照片不进入历史。编辑器仅加载当前关联照片，提交前重新校验人工结论引用的照片仍属于当前记录。报告保留历史提交照片，并以图片编号关联其识别尝试。

识别仅允许在草稿或退回补正时发起。尝试编号在记录锁内分配，模型调用在数据库事务外执行，候选与成功状态共同提交。调用或候选保存失败时保留失败尝试，不覆盖先前结果。

检测按固定病害类别分工：裂缝、泛碱和苔藓使用专项权重，表面剥落使用独立权重，其余类别使用主权重。同类别不合并多份候选，输出按统一坐标系重新编号；各模型推理串行，任一模型失败均保留为失败尝试。模型版本对应权重清单及类别分工，可追溯到各成员的哈希。

识别端可通过 `spalling_weights_path` 配置独立的表面剥落权重，并通过 `spalling_confidence_threshold` 单独设置其候选阈值；未单独设置时使用通用阈值。配置权重后仅使用该模型的表面剥落候选，并与其他类别结果共用原图坐标。缺少已配置权重或推理失败时返回失败尝试，未配置时不输出该自动类别。

局部训练的剥落权重可通过 `spalling_tile_size` 启用分块推理，值为训练裁剪边长；默认 0 表示整图推理。分块重叠覆盖图像边缘，同类别重叠框按置信度合并，结果换算回原图坐标。为限制大图的推理开销，长边超过裁剪边长三倍时先等比例缩小。

原始照片按上传字节保存，content 接口提供原件。preview 接口复用原件访问权限，应用 EXIF 方向并去除元数据，保留完整像素尺寸。管理端、巡检端叠框和报告使用同一方向标准化规则，与识别端坐标系一致。上传须通过真实格式、内容解码和 6,400 万像素上限校验。巡检端可选择概览或细节图独立识别，切图时按图片展示候选和辅助分析。

人工定位框可省略；提供时必须包含四个有效数值坐标、正面积并处于方向归一后的照片范围内。边界校验复用预览解码规则，不依赖原件的编码尺寸；同次保存对同一照片复用已计算的尺寸。任何无效框都会拒绝整次结论保存，不新增结论版本或改变记录 revision。

巡检端支持在当前照片上拖动框选并补录病害，框选坐标换算为方向归一后的原图像素。巡检端和管理端的记录详情按当前或选定提交版本展示对应的人工补录框；报告照片叠加最新人工结论中的补录框。未框选时仍可通过照片和文字补录。

任务巡检与主动上报共用现场记录编辑器，复用照片、识别、人工复核和草稿恢复逻辑。主动上报提交时须提供定位和现场描述；提交成功后进入只读记录详情，退回后可继续补正。

位置更新和提交校验经纬度完整性、WGS84 数值范围及非负定位精度。任务记录保存与提交时按派发快照坐标计算球面近似距离，保留两位小数；点位档案的后续变更不影响任务目标和提示半径。提交快照同时冻结偏移和半径。两端记录详情及报告提示超出任务半径和精度超过 30m 的位置，提示不阻止提交或人工审核。

巡检编辑器串行处理照片上传与移除，按照片编号更新当前关联。照片处理、识别或定位尚未结束时禁止保存与提交，保存提交期间禁止重新定位。定位失败保留原位置并明确提示，离开页面后忽略定位回调。离页后不再更新照片视图，并释放迟到响应产生的预览资源。

问题独立于任务流转，支持指派、处理、观察、核验和关闭。报告使用只读可重复读事务加载跨表数据，照片、人工结论、复核、问题状态与处置历史来自同一数据库快照。处置进展包含操作人、处理与观察内容、核验过程及计划复查时间；既有报告不跟随后续记录变化。

任务和时间范围报告保留按提交顺序排列的全部审核记录，分别展示审核人、时间、处置意见和审核原因。重新提交后尚未审核的记录明确标记为待审核，较早的退回意见作为历史保留。

两类报告使用相同的证据明细，保留识别状态、候选类别与坐标、各版人工结论描述、逐项判定及人工定位框。业务状态、来源和病害类别以中文展示，接口与报告数据快照仍保存原始业务编码。

管理端问题详情展示观察动作的计划复查时间；管理员、审核员和当前问题责任人可展开关联的已审核现场记录，查看原记录的照片、识别候选、人工结论及复核意见。问题指派只授予关联记录的只读权限，不改变来源记录的修改权限和个人记录检索范围；改派后原责任人失去通过该问题访问来源证据的权限。

问题台账支持名称或位置、状态、优先级、本人责任、未关闭和到期复查筛选。观察中的问题以最近一次观察记录的计划时间为当前复查安排；新观察未设时间时清除当前安排，处理进展、核验和关闭状态不沿用旧提醒。工作台与台账使用相同查询条件计数，到期提示不自动改变问题状态。详情地址通过 issue_id 保留所选问题，姓名和档案名称展示当前目录值，历史动作内容保持不变。

问题责任人、管理员及审核员可在问题可处理期间为本人动作补充照片，待核验或已关闭时冻结上传。图片元数据、动作关联及问题版本在问题锁内共同提交，失败时回滚并清理未提交文件。附件原件与标准化预览按问题访问权限读取，改派后的原责任人不再拥有该问题附件的读取权限。管理端显示处置照片，任务与时间范围报告将照片纳入生成时刻的快照。

尚未受理的审核通过记录可从记录检索继续受理。受理时间、操作人与不立项原因保存在记录中，记录详情和报告均可查询。受理在现场记录锁内完成，新增问题、关联关系与受理结果共同提交；每条记录只受理一次，重复请求返回既有结果。问题关闭时同时保存当前关闭时间和原因；重新打开清除当前关闭标记，历次核验与重开动作保留在处置时间线中。

指派、处置动作、申请核验、核验和重开均在事务内锁定问题并校验版本，状态、责任人和动作记录共同提交。写入失败时整体回滚，同一版本的并发操作只有一次成功。对应审计事件在业务事务提交后记录，保留真实的变更前后状态。

问题指派由管理员从启用的业务用户中选择责任人，候选仅返回编号和显示名称。保存时再次校验账号状态与业务角色，不接受不存在或停用的账号。

## 部署

Docker Compose 运行 MySQL、Go、Python 和 nginx。容器间通过服务名连接。MySQL 数据与业务文件采用独立命名卷，配置只读挂载；YOLO 权重从 data/yolo 挂载。识别服务仅在内部网络开放。

开发者通过主机执行单元测试和前端构建。隔离业务测试采用独立 Compose 项目和端口，结束后删除该项目的容器与卷。

## 人工判断边界

检测置信度不表示病害严重度，零检测不等于正常。视觉模型的可能成因和建议为辅助文本，不能成为结构安全鉴定。模型与分析服务不可用时可人工填写现场记录，不能伪造模型输出。
